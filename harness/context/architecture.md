# Архитектура проекта

Статический сайт на React 19.2.8, TypeScript, Vite 8, React Three Fiber 9.7.0
и three.js 0.160.1. Dev-проверки используют `@react-three/test-renderer` 9.1.1.
Версии и команды — в [package.json](../../package.json), правила работы —
в [AGENTS.md](../../AGENTS.md). Серверного приложения и базы данных нет.
Локальная разработка и GitHub Actions используют Node 24.x.

## Основания решений

Разделение генератора принято в
[плане миграции](../../docs/typescript-migration-plan.md), результат проверен
в [отчёте приёмки](../../docs/typescript-migration-validation.md).
TypeScript выбран, чтобы одна модель могла строиться в Node.js и будущем
браузерном редакторе. Отдельный пакет или монорепозиторий для этого не вводился.

Первый этап намеренно сохранил мировые координаты, формат данных и поведение
просмотрщика. Собственные сериализаторы сохранены для совместимости экспортов;
переход на другой экспортёр не был частью переноса. Просмотрщик перенесён на
R3F; решения реализации и результаты приёмки описаны в
[плане](../../docs/r3f-viewer-migration-plan.md) и
[отчёте](../../docs/r3f-viewer-migration-validation.md). Предметная иерархия
и редактор отложены решением пользователя 2026-09-09. Подробные планы остаются
в `docs/`; ниже описана только существующая реализация.

## Интерфейс и загрузка

`src/main.tsx` монтирует React в StrictMode. `src/App.tsx` хранит настройки
просмотра и соединяет компоненты панели, области просмотра и нижних кнопок.
React управляет интерфейсом и сценой R3F; внешний контракт остаётся через
`ViewerHandle` из `src/viewer/types.ts`.

`src/hooks/useApartmentViewer.ts` одновременно загружает `model.json` и
динамически импортирует `src/viewer/index.tsx`. `src/model/parse-model.ts`
проверяет данные до создания сцены. Хук передаёт актуальные настройки
в `createViewer`, хранит handle в ref и возвращает статус `loading/ready/error`.
Изменения настроек идут через `setOptions`, без пересоздания просмотрщика.
Cleanup отменяет загрузку через AbortController и вызывает `dispose`.

Модель загружается по пути с `import.meta.env.BASE_URL`; этот же префикс
используется для скачивания GLB. Просмотрщик строит сцену из JSON, GLB служит
отдельным экспортом. `vite.config.ts` задаёт относительный `base: './'` для
публикации в подкаталоге. Ресурсы сайта загружаются со своего сервера.

## Сцена и ресурсы

- `src/viewer/index.tsx`: создание canvas/renderer, конфигурация R3F root,
  ResizeObserver, ready/error callbacks и общий `dispose`.
- `ApartmentScene.tsx`: декларативный свет, общие геометрии, материалы, группы
  деталей, отсечение стен и мебели на 1,05 м, поверхности срезов.
- `scene-resources.ts`: пул общих ресурсов сцены и его ручной cleanup.
- `camera.ts`: камера, вращение, перемещение, масштабирование и вписывание.
- `controls.ts`: события canvas, pointer capture, мышь и жесты двумя пальцами.
- `labels.ts`: DOM-подписи комнат поверх canvas.
- `measurements.ts`: состояние выбора, расчёт результатов и SVG-размеры поверх
  сцены; `measurement-picking.ts` учитывает видимость, срез и поверхности среза.
  `controls.ts` отделяет нажатие от жеста и поддерживает выбор с клавиатуры.
  `MeasurementPanel` получает снимки состояния через хук; команды выбора идут
  через `ViewerHandle.measurement`.
- `options.ts` и `types.ts`: режимы, начальные настройки и контракты API.

Отрисовка выполняется R3F по запросу; постоянного цикла нет. Изменения камеры,
настроек и размера инвалидируют root.
Смена режима заново вписывает модель. Потолок в просмотрщике скрыт.

Общий `dispose` идемпотентен: отключает ResizeObserver и DOM-обработчики,
удаляет подписи и SVG измерений, размонтирует R3F root, освобождает renderer и удаляет canvas.
R3F останавливает отрисовку root и очищает JSX-материалы и свет с shadow map;
общий пул освобождается cleanup-эффектом `ApartmentScene`. Внутренняя очистка
root и потеря WebGL-контекста отложены библиотекой на 500 мс, поэтому каждый
новый просмотрщик получает отдельный canvas. Это изолирует повторные mount
и Fast Refresh от очистки предыдущего экземпляра.

Камера помечена `manual`, чтобы R3F не менял её frustum при resize. Компонент
`ViewerFrame` обновляет камеру и DOM-подписи перед отрисовкой, пропускает
нулевые размеры и разрешает `ViewerHandle.ready` после подготовки первого
кадра. Загрузчик ждёт этот promise; ошибки fetch/import/валидации,
инициализации WebGL и границы React переводят его в прежнее состояние error.

## Генерация модели

`src/modeling/build-apartment.ts` собирает квартиру через независимый builder:
общая оболочка из `shell/`, композиции комнат из `rooms/`, повторяемая мебель
из `furniture/`, примитивы и материалы из `core/`. Каждый вызов `buildApartment()`
возвращает независимые данные. Формат описан в `src/model/types.ts`:
метаданные, материалы, плоский массив деталей и подписи комнат.

Общие размеры и привязки плана находятся в `src/modeling/plan.ts`. Оболочка
и комнаты используют эти опорные значения; источник и согласование подписей
с вектором PDF описаны в `docs/plan-dimension-audit.md`. Размеры шкафов
включают фасады и ручки. Данные остаются плоскими примитивами.

Детали имеют мировые координаты; иерархии редактируемых предметов пока нет.
Единицы — метры, Y направлен вверх.
Соглашения аргументов примитивов — в `core/builder.ts` и `AGENTS.md`.

`src/modeling/measurements.ts` добавляет отдельный каталог измерений версии 1:
предметные ID, размеры в локальных осях, контуры проекций и источники размеров.
На этапе генерации явный реестр связывает детали по именам/префиксам и опорным
координатам; пустые, повторные назначения и непривязанная мебель вызывают ошибку.
Просмотрщик использует только записанный `measurementId`, имена деталей не разбирает.
Габариты рассчитываются аналитически; контуры предметов представлены объединением
проекций примитивов. Эллипсы приближены многоугольниками с отклонением до 0,5 мм
на контур. Контуры четырёх комнат заданы по внутренним граням стен через `PLAN`.

Общие типы и чистая математика находятся в `src/model/measurement-types.ts` и
`measurement-math.ts`; `parse-measurements.ts` валидирует каталог, ссылки и контуры.
Поле `measurements` необязательно: прежние JSON загружаются без возможности измерений.
Это дополнение плоского формата, без перестройки генератора в редактор предметов.

`src/modeling/export/` сериализует модель в JSON, GLB и OBJ/MTL, возвращая
строки и байты. Генератор и сериализаторы не используют файловую систему,
React, DOM или WebGL. Общий код пригоден для браузера, но текущий интерфейс
загружает готовый JSON и не запускает генератор.

Только `scripts/build-model.ts` разбирает аргументы CLI и записывает экспорты
в `public/models/apartment/`. `--check` сравнивает результат без записи;
`--output-dir` позволяет выбрать другую папку. Генерируемые файлы вручную
не редактируются. Зависимости направлены от `modeling/` к общим типам `model/`;
рантайм не должен зависеть от сборочного CLI.

## Проверки и публикация

`.gitattributes` закрепляет LF для текстовых файлов независимо от локального
`core.autocrlf`, чтобы checkout на Windows соответствовал требованиям Prettier.
Бинарные файлы распознаются Git автоматически.

Node-тесты в `tests/` проверяют валидацию данных, генератор, сериализацию
и импорт экспортов, CLI, сцену и математику камеры. Они не запускают
полноценный браузерный просмотрщик. Работа с историческими и текущими
эталонами описана в [tests/fixtures/README.md](../../tests/fixtures/README.md).
Порядок команд и браузерные проверки — в `AGENTS.md`.

`npm run build` проверяет актуальность экспортов и TypeScript, затем создаёт
`dist/`. `.github/workflows/deploy-pages.yml` выполняет тесты и сборку перед
публикацией GitHub Pages; триггеры — push в `main` и ручной запуск workflow.
Наличие workflow не подтверждает состояние опубликованного сайта.
