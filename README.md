# Хатка — 3D-модель квартиры

Сайт на React, TypeScript, React Three Fiber, Three.js и Vite, подготовленный из архива `apartment-3d.zip`.
Модель основана на исходной планировке и уточняется по правкам. Интерфейс на русском языке.

## Запуск

Нужен Node.js 24.x с npm. Эта же версия используется в GitHub Actions.

```sh
npm install
npm run dev
```

Откройте <http://127.0.0.1:5173>. На Windows при блокировке `npm.ps1` используйте
`npm.cmd install` и `npm.cmd run dev`.

Для повторной установки точных версий из `package-lock.json` используйте `npm ci`.
Интернет нужен для установки зависимостей. Сам сайт загружает библиотеку и модель
со своего сервера; внешних CDN, шрифтов и сервисов нет.

## Команды

| Команда                | Назначение                                          |
| ---------------------- | --------------------------------------------------- |
| `npm run dev`          | Локальный сервер с обновлением при изменении файлов |
| `npm run build`        | Проверка экспортов и типов, сборка сайта в `dist/`  |
| `npm run preview`      | Просмотр сборки на <http://127.0.0.1:4173>          |
| `npm test`             | Проверка генератора, экспортов, CLI, сцены и камеры |
| `npm run typecheck`    | Строгая проверка TypeScript, включая CLI и тесты    |
| `npm run model:build`  | Пересоздать JSON, GLB, OBJ и MTL                    |
| `npm run model:check`  | Проверить актуальность экспортов без записи файлов  |
| `npm run format`       | Форматирование TypeScript, TSX, CSS и документации  |
| `npm run format:check` | Проверка форматирования                             |

Открывать `index.html` двойным щелчком не нужно: ES-модули и загрузка JSON требуют
HTTP-сервера. Для публикации на статическом хостинге используется содержимое `dist/`.
Относительные пути в настройке Vite позволяют размещать сборку в подкаталоге,
в том числе на GitHub Pages.

### GitHub Pages

В репозитории уже есть workflow `.github/workflows/deploy-pages.yml`: он запускает
тесты, проверяет актуальность экспортов, собирает проект и публикует `dist/`
после каждого push в ветку `main`. Один раз включите
`Settings → Pages → Build and deployment → Source: GitHub Actions`. После этого
адрес опубликованного сайта появится в окружении `github-pages` у workflow.

`reference/` не участвует в сборке. Его README описывает расположение файлов
в исходном архиве; актуальная структура приведена выше. `viewer-fragment.html`
содержит шаблон с подстановкой модели, а `viewer.html` — старую автономную версию
с внешними CDN. Код для дальнейшей разработки находится в `src/`.

React управляет интерфейсом и декларативной сценой R3F. Fiber и Three.js
подключаются ленивым модулем при загрузке модели. Типизированный `ViewerHandle`
связывает настройки и команды камеры с просмотрщиком. Переключатели обновляют
существующую сцену, сохраняя положение камеры;
смена режима просмотра заново вписывает квартиру.

Хук `useApartmentViewer` отменяет незавершённую загрузку при размонтировании и освобождает
canvas, геометрию, материалы, наблюдатель размера и обработчики жестов. Это также
поддерживает повторный запуск эффектов в StrictMode и React Fast Refresh.
Проверка TypeScript включена в сборку; тесты TypeScript запускаются через `tsx`.

## Управление

- **Вид:** разрез на высоте 1,05 м, полные стены 2,70 м или план сверху.
- **Вращение:** левая кнопка мыши; также кнопки ↶ и ↷.
- **Перемещение:** правая/средняя кнопка мыши, Shift + перетаскивание либо кнопка «Перемещать».
- **Масштаб:** колёсико к точке под курсором, кнопки −/+ или жест двумя пальцами.
- **Вписать модель:** вернуть всю квартиру в видимую область.
- **Мебель / Названия:** переключение видимости. В режиме полных стен названия скрыты.

На узких экранах в 3D остаются подписи основных комнат; в плане сверху отображаются все.
Для 3D нужен браузер с WebGL. При ошибке запуска остаётся ссылка на скачивание GLB.

## Изменение модели

2026-09-10 модель и расстановка приведены к «Итоговая планировка.pdf», лист 09.
Оболочка, окна, проёмы, полы и мебель используют общие опорные размеры
из `src/modeling/plan.ts`. Подписанные размеры имеют приоритет над вектором;
реестр и согласование противоречий — в [аудите планировки](docs/plan-dimension-audit.md).

В большом санузле зона ванны имеет габарит 1835 × 800 мм, двойная тумба —
500 × 1250 мм; в малом санузле вместо прежней душевой размещена ванна
в зоне 820 × 1499 мм. Кухонная мойка находится над вторым модулем.
В кабинете стол занимает всю нижнюю стену шириной 3278 мм, левая часть —
700 × 1356 мм; у окна подоконная тумба. В спальне восстановлен рабочий стол
1356 × 500 мм с зазором 569 мм до кровати. Прежняя кастомная расстановка
заменена по указанию пользователя.

Проверены все 64 размерные линии. Неподписанные координаты получены
из вектора PDF с проверенным масштабом; они не являются обмером.
Высоты мебели, проёмов и декоративные детали остаются схематичными.

Генератор полностью написан на TypeScript. Python для работы проекта больше не нужен.
Расстановка задаётся в `src/modeling/rooms/`, повторно используемая мебель —
в `src/modeling/furniture/`, материалы — в `src/modeling/core/materials.ts`.
Общие стены, полы и проёмы находятся в `src/modeling/shell/` и создаются один раз.

После изменения генератора пересоздайте файлы модели:

```sh
npm run model:build
```

На Windows при блокировке `npm.ps1` используйте `npm.cmd run model:build`.
Команда обновляет `model.json`, GLB, OBJ и MTL в `public/models/apartment/`.
Путь по умолчанию вычисляется относительно скрипта, а не текущей рабочей папки.
Затем обновите страницу; для публикации снова выполните сборку.

Чтобы сохранить результат в отдельную папку:

```sh
npm run model:build -- --output-dir .tmp/model-export
```

Просмотрщик строит геометрию из `model.json`; GLB служит отдельным экспортом.
Ручные изменения JSON будут перезаписаны при запуске генератора. Команда
`npm run model:check` проверяет все четыре экспорта без изменения файлов;
она также выполняется перед сборкой сайта, чтобы не публиковать устаревшую модель.
После изменения модели включайте её обновлённые экспорты в ту же правку.
`preview.png` и
`docs/original-validation.json` сохранены из архива и автоматически не обновляются.

Текущая модель сверена с PDF; размеры указаны в метрах. Источник, согласования и ограничения —
в [аудите планировки](docs/plan-dimension-audit.md). Исторические допущения реконструкции
по фотографии сохранены в [описании исходной модели](reference/README.md).

## Доработка помещения

1. Откройте соответствующий модуль: например, `src/modeling/rooms/kitchen.ts`
   или `src/modeling/rooms/study.ts`.
2. Меняйте композицию помещения; общие детали предметов дорабатывайте в `furniture/`.
   Система координат: X вправо, Y вверх, Z вниз по исходному плану; единицы — метры.
   `box` принимает левый верхний угол на плане, цилиндры и эллипсоиды — центр.
   Углы примитивов задаются в радианах, вспомогательная функция дверей — в градусах.
3. Выполните `npm run model:build`, затем проверьте модель в трёх режимах.
4. Запустите `npm test` и `npm run build`. Тест генератора сравнивает квартиру с
   отдельным эталоном текущей планировки: при намеренных изменениях планировки явно
   пересмотрите его согласно `tests/fixtures/README.md`.

`buildApartment()` каждый раз создаёт независимую модель. Общий генератор и
сериализаторы не обращаются к файловой системе, React или WebGL; их можно использовать
в браузере. Только `scripts/build-model.ts` разбирает аргументы и записывает файлы.

Перенос на TypeScript сохраняет нынешний формат модели и мировые координаты деталей.
Просмотрщик перенесён на React Three Fiber с сохранением модели и управления;
решения реализации и программа приёмки — в [плане R3F](docs/r3f-viewer-migration-plan.md)
и [отчёте приёмки](docs/r3f-viewer-migration-validation.md).
Предметные идентификаторы, локальные координаты, переделка генератора под предметы
и перетаскивание отложены решением пользователя от 2026-09-09;
они остаются в [бэклоге](docs/room-rework-backlog.md).
