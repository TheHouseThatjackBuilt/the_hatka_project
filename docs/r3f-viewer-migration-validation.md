# Приёмка перехода просмотрщика на R3F

Дата: 2026-09-09. Переход реализован. Отчёт относится к локальному запуску
после миграции, а не к опубликованному сайту или будущим изменениям.
Решения и программа проверки — в [плане](r3f-viewer-migration-plan.md).

## Результат

Сцена собирается в `ApartmentScene.tsx`; старые императивные `viewer/index.ts`
и `viewer/scene.ts` удалены. Fiber управляет деревом и отрисовкой по запросу.
Математика камеры, DOM-жесты и подписи сохранены. Canvas создаётся адаптером
`createRoot`. Внешний `ViewerHandle` дополнен promise `ready`: интерфейс ждёт
подготовки первого кадра, ошибки остаются в прежнем состоянии `error`.

Генератор, формат модели, геометрия, экспорты и исторические эталоны не изменены.
`model:check` подтверждает прежние 761 деталь. Предметные ID, переделка
генератора и редактор остаются отложенными. Новых пользовательских функций
этот этап не добавляет.

## Зависимости и автоматические проверки

Установлены точные `@react-three/fiber` 9.7.0 и dev-зависимость
`@react-three/test-renderer` 9.1.1. `npm ls` подтверждает единственные версии
React/ReactDOM 19.2.8 и Three 0.160.1; зависимые пакеты используют их совместно.

| Проверка                                     | Результат                            |
| -------------------------------------------- | ------------------------------------ |
| `npm run typecheck`                          | Пройдена                             |
| `npm run test`                               | 27 из 27                             |
| `npm run build`                              | Пройдена, включая `model:check`      |
| Изменения `src/modeling/` и `public/models/` | Отсутствуют                          |
| Форматирование изменённых файлов             | Проверено отдельно                   |
| Общий `npm run format:check`                 | 34 прежних файла с CRLF; список ниже |

Тесты просмотрщика монтируют реальный компонент через test-renderer, тестовую
модель получают из `buildApartment()`. Проверяются все трансформации и цвета,
потолок, мебель, clipping, поверхности срезов, направление света, сохранение
mesh/material/geometry при изменении props, fit в 1200×700 и 360×500,
последовательное масштабирование вокруг курсора.

Два mount/unmount под оболочкой StrictMode подтверждают: на активной модели
три общие геометрии, новый mount получает свежие ресурсы, refs очищаются,
каждый ресурс освобождается один раз. Проверка не предполагает конкретного
числа повторов эффектов внутри React-реконсайлера.

## Сравнение изображения

Исходные снимки сделаны до изменения рабочего пути. Сравнение проведено
в одном встроенном Chromium-браузере, тёмной теме и DPR 1, при размерах окна
1200×850 и 360×650. Размеры canvas — 1158×673 и 334×347. После изменения
размера для сравнения использовалось одинаковое вписывание модели.

| Вид                           | Результат                                                                                                                           |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `full`, широкий и узкий экран | Скриншоты совпали пиксель в пиксель                                                                                                 |
| `top`, широкий и узкий экран  | Скриншоты совпали пиксель в пиксель                                                                                                 |
| `cut`, широкий экран          | Кадрирование и все 9 координат подписей совпали; средняя абсолютная разница каждого RGB-канала в canvas меньше 0,017 на шкале 0–255 |
| `cut`, узкий экран            | Визуальное совпадение; средняя разница каждого канала меньше 0,0032 в canvas                                                        |

Разрез не объявляется побитово идентичным: различия локальны и малы.
Размеры, материал и трансформация каждой детали проверены отдельно тестами.
Снимки и диагностические страницы оставлены локально в игнорируемой
`.tmp/r3f-validation/`; они не входят в production и не являются эталонами
генератора.

## Браузерное поведение

- Проверены `cut/full/top`, скрытие мебели с переходом `full → top`
  и обратным включением. Поверхности срезов согласованы с мебелью.
- Переключатель названий скрывает и возвращает подписи. В `full` их нет,
  в `top` видны все девять. В `cut` при ширине canvas 499 видны три,
  при 500 — девять.
- Проверены вращение мышью, переключатель перемещения, кнопки вращения,
  масштаба и вписывания, wheel. Подписи обновляются вместе с камерой.
- В диагностической странице событиями PointerEvent проверены Shift-pan,
  средняя/правая кнопка, два указателя с pan/pinch, отмена одного указателя,
  `lostpointercapture` и возврат к одиночному жесту. Перемещение на −50/+30
  пикселей даёт такое же перемещение подписи, без удвоения обработчиков.
- Проверены resize после взаимодействия и переход ненулевой размер → нулевой
  → ненулевой. При нулевом размере кадр не пересчитывает проекцию камеры;
  после восстановления размеров сцена снова отображается.
- После загрузки счётчик WebGL-кадров равен 1 и не растёт в покое.
  После четырёх диагностических жестов он равен 5 и также останавливается;
  очередь кадров пуста, режим root — `demand`.

Активная сцена содержит один canvas, девять DOM-подписей, семь обработчиков
управления, три GPU-геометрии и одну texture карты теней. После повторного
монтирования значения те же. После unmount и завершения отложенной очистки
R3F: ноль roots/canvas/подписей/обработчиков.

Сбой браузерного инструмента прервал первую попытку проверки remount.
После восстановления подключения проверка выполнена повторно; незавершённая
попытка не использовалась как доказательство.

## Загрузка, ошибки и production

Проверены холодная и медленная загрузка, отмена загрузки до ответа,
HTTP 404, синтаксически неверный JSON, неверная структура модели и отказ
создания WebGL-контекста. Ошибки показывают прежний текст и ссылку на GLB;
`aria-busy` становится false, команды остаются отключёнными. После ошибок
и отмены нет позднего canvas или оставшихся обработчиков.

В прототипе `Canvas` 9.7.0 исключение из фабрики `gl` оставалось необработанной
async-ошибкой вне React boundary. Поэтому адаптер создаёт WebGLRenderer явно,
ожидает `root.configure()` и передаёт ошибки в существующий путь загрузчика.
Отдельный canvas на mount изолирует отложенную очистку предыдущего root.

Готовый `dist/` запущен локальным статическим сервером по пути `/hatka/`.
Все три режима работают, canvas один, JSON и JS загружаются по относительным
путям, ссылка разрешается в `/hatka/models/apartment/apartment.glb`, ответ —
HTTP 200. В рабочем dev-просмотрщике и production новых ошибок консоли
не обнаружено. Намеренно вызванные отказы диагностической страницы
рассматривались отдельно.

## Размер сборки

Размеры из вывода Vite, kB / gzip kB:

| Часть                   | До              | После           |
| ----------------------- | --------------- | --------------- |
| Начальный JS интерфейса | 197,68 / 62,75  | 198,40 / 63,08  |
| Ленивый JS просмотрщика | 471,10 / 119,30 | 618,29 / 165,68 |
| CSS                     | 3,25 / 1,19     | 3,25 / 1,19     |

Fiber остаётся за ленивой границей. Его цена — около 46,38 kB gzip
дополнительного кода просмотрщика. Vite предупреждает о чанке больше 500 kB;
лимит предупреждения и конфигурация сборки не изменялись. Ускорение загрузки
или отрисовки не заявляется.

## Ограничения проверки

Два указателя проверены синтетическими событиями в настоящем DOM/WebGL,
а не на физическом сенсорном экране. Реальный мультитач, смена физического DPR,
сбой отдельного JS-чанка и восстановление потерянного WebGL-контекста
отдельно не воспроизводились. Проброс ошибки импорта проверен по коду загрузчика.
Браузерная программа не включена в CI; Node-тесты не заменяют её.
