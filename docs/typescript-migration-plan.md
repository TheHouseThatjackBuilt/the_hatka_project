**Переход генератора квартиры на TypeScript**

Дата: 8 сентября 2026 года. Статус: первый этап реализован; итоговые проверки описаны в `typescript-migration-validation.md`. React Three Fiber и редактор остаются следующим этапом.

Пользователь выбрал TypeScript для генератора и React Three Fiber следующим шагом. Предыдущее предложение сохранить Python больше не является целевым решением. Python допускает модульное развитие, но общий TypeScript-код удобнее для будущего изменения параметров мебели непосредственно в браузере.

**Цель первого этапа**

Получать текущую квартиру и все существующие экспорты полностью средствами Node.js/TypeScript. Общие функции построения модели должны импортироваться как из командной строки, так и из будущего браузерного редактора. После приёмки Python не нужен для генерации, тестов и сборки.

На этом этапе сохраняются текущая геометрия, мировые координаты, материалы, три режима просмотра и формат model.json, который понимает существующий viewer. Помещения и функции создания мебели распределяются по модулям. Переход деталей на локальные координаты предметов и новая схема редактирования идут следующим этапом вместе с подготовкой R3F-сцены.

Это структура реализованного генератора. Отдельный пакет или монорепозиторий не нужен. Сериализаторы не обращаются к DOM или диску; запись файла выполняет CLI, а в будущем браузер сможет организовать скачивание из тех же строк и байтов. Реализация кнопки скачивания текущей расстановки не входит в первый этап.

Функции сборки возвращают данные. Не должно быть глобального накопительного PARTS и построения квартиры при импорте. Каждый вызов использует свой контекст. На первом этапе примитивы могут сохранить текущие сигнатуры и расчёты мировых координат, чтобы локализовать различия при переносе.

Оценка — человеко-часы одного разработчика, знакомого с текущими исходниками, включая локальные проверки. С резервом ориентир 22–38 часов. Это отдельный ограниченный результат, не оценка всего редактора и не календарный срок работы агента. Он частично заменяет A/B/F предыдущего бэклога; прибавлять его целиком к старым итогам нельзя. Общую оценку следует пересчитать после определения объёма R3F-миграции.

**Как проверить перенос**

- Сначала проверить, совпадает ли текущий Python-генератор с сохранёнными артефактами. Не заменять неизвестные различия автоматически.
- Для текущего model.json зафиксированы 761 деталь, 20 материалов и 9 подписей. Сравнивать не только количество, но также форму, категорию, имя, материал, позицию, размер и угол каждой детали.
- Пока сохраняется порядок деталей, можно сопоставлять их по индексу и имени вместе. Это временный способ проверки миграции; в редакторе понадобятся независимые стабильные id.
- Проверить отличия округления Python и JavaScript, особенно около половинных значений, отрицательных чисел и мест, где round определяет число секций мебели. Не менять молча геометрию ради формального сходства кода.
- Для координат и углов установить небольшой явный допуск, согласованный с исходной точностью 5 и 6 знаков. Показать отличия, превышающие его.
- Для GLB проверять структуру, индексы, нормали, трансформации, материалы и независимые деревья двух сцен. Для OBJ — вершины, грани, материалы и поведение потолка. Различия форматирования/порядка JSON-ключей не считать геометрической регрессией.
- Проверять сериализаторы независимо от функций, которыми они строятся: чтение GLB через существующие средства Three.js, сверка с эталонными данными, просмотр экспорта при доступности импортера.
- Проверить повторную сборку в одном процессе и независимость результатов двух вызовов.
- Проверить импорт общего генератора браузерной сборкой без Node.js-зависимостей; проверка TypeScript сама по себе этого не гарантирует.
- Выполнить существующие тесты, проверку типов, сборку и визуальное сравнение трёх видов сайта. Отдельно убедиться, что экспортируемая геометрия совпадает с моделью сайта.

**Почему сохраняем нынешний способ экспорта на этапе переноса**

Генератор содержит небольшой собственный экспортёр на стандартной библиотеке. Его можно перенести на типизированные массивы и DataView, сохранив поведение. Одновременная замена его библиотечным экспортёром потребует отдельно разбирать отличия материалов, групп и двух сцен. Сначала сохраняем результат; замену сериализатора при необходимости можно оценить отдельно. Текстуры, внешние ассеты и произвольные импортированные меши пока не входят в поддерживаемый генератором набор.

**Следующий этап: предметная модель и React Three Fiber**

1. Ввести сущности помещений и предметов со стабильными id, правилами движения и локальными деталями; исходную расстановку отделить от геометрии. Проверить сохранение итоговых мировых преобразований.
2. Подобрать согласованные версии React, Fiber, Three.js и их типов. Точные версии зафиксировать по peerDependencies выбранных релизов, а не только по примерам документации.
3. Перевести текущий просмотрщик на R3F: canvas, создание сцены, свет, материалы, камера, разрез, подписи, управление, обновление по запросу и освобождение ресурсов. Сохранить поведение до добавления редактирования.
4. После визуального и функционального совпадения делать выбор, drag, поворот, историю и сохранение уже в R3F-просмотрщике. Модель данных и команды остаются независимыми от React.

Так мы не реализуем полноценную новую иерархию объектов и редактор дважды в разных способах управления сценой. Этап C предыдущего бэклога нужно переработать под R3F; этапы D/E сохраняют продуктовую цель, но их технические задачи и оценки требуют актуализации.

**Инструменты**

Node.js, TypeScript и tsx уже есть в проекте. tsx можно использовать для запуска scripts/build-model.ts, а Vite — для сборки того же общего TS-кода в браузер. tsx запускает код, проверка типов остаётся отдельной обязанностью tsc. Новый Python-интерпретатор, сервер и WASM для такого переноса не требуются. [Документация tsx](https://tsx.is/getting-started).

R3F — отдельный React-renderer поверх Three.js, поэтому общий генератор должен выдавать данные и не импортировать React-компоненты. Установка и совместимость версий проверяются на следующем этапе. [Установка R3F](https://r3f.docs.pmnd.rs/getting-started/installation).
