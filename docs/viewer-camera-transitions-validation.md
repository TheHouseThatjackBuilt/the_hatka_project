# Приёмка R3.2 — управление и переходы камеры

Дата: 2026-09-20. Этап из [плана редизайна](viewer-redesign-plan.md).

## Результат

- `ViewerHandle.fit()` вписывает видимую модель, сохраняя ракурс.
- `reset()` возвращает ракурс первого открытия и режим «Срез»; `top()` включает
  план сверху. Повторное top восстанавливает ориентацию и кадрирование плана.
  Режим в React, переключатель и статус синхронизированы с этими командами.
- Fit, reset, top и смена режима используют 450 ms easeInOutCubic. Первый кадр
  и автоматическое вписывание после resize остаются непосредственными.
- Однопальцевый drag/мышь плавно вращают и перемещают камеру: остаток движения
  затухает экспоненциально с постоянной времени 45 ms и конечным порогом остановки.
  Wheel и pinch обрабатываются сразу, сохраняя привязку масштаба к курсору/центру жеста.
- Новая команда, pointerdown, wheel или другой вид движения прерывают прежний
  переход в текущей позе. Переход выбирает короткую дугу поворота.
- Матрицы камеры, измерения, picking и подписи обновляются в одном кадре R3F.
  Собственного RAF или таймера анимации нет; после остановки demand loop засыпает.
- `prefers-reduced-motion: reduce` отключает переходы и затухание. Изменение
  настройки во время перехода завершает его сразу; listener удаляется при dispose.

Сброс в cut выбран как трактовка «исходного ракурса» из брифа, а не отдельное
подтверждённое пользователем предпочтение. Геометрия и экспорты не менялись.
Подсказка первого посещения остаётся R3.3.

## Автоматические проверки

На Node 24.14.0 успешно выполнены `npm run typecheck`, `npm run test`
(73 теста), `npm run build` с `model:check`, `npm run format:check`.

Пять новых тестов камеры проверяют начальную непрерывность full/cut, конечные
матрицы, остановку кадров, fit/reset, прерывание и замену перехода, короткую дугу,
значение cubic easing на четверти длительности, затухание при 30/144 Hz,
точный результат pan, нижний предел наклона, reduced motion, якорь zoom
и восстановление после нулевого размера. Существующие проверки выбора,
жестов, resize и освобождения ресурсов проходят.

Сборка предупреждает о viewer chunk 634,39 kB (172,02 kB gzip); предупреждение
о размере chunk существовало до этого этапа и не прерывает сборку.

## Браузер

Проверены dev и production preview во встроенном Chromium:

- cut/full/top, отдельные fit/reset/top, поворот и масштаб кнопками;
- вращение мышью, pan с Shift, wheel, активация камеры с клавиатуры;
- закреплённый размер дивана сохраняется при top/reset; переключатели мебели
  и названий, открытие и закрытие измерений;
- desktop 1280×720, mobile 320×740 и 390×844, короткое окно 844×390;
  восемь кнопок доступны, горизонтального переполнения панели нет;
- resize с переукладкой UI и вписыванием; полный вид скрывает подписи;
- финальная production-страница без ошибок консоли.

[Диагностическая страница](assets/camera-2026-09-20/probe.html) запускается только
через Vite dev, импортирует настоящий App и не входит в production entry.
Она измеряет renderer через `_roots` установленной R3F; это диагностический,
а не новый публичный API приложения. Результаты:

| Сценарий                  | Результат                                                                                     | Артефакт                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Top/reset и покой         | Промежуточные матрицы меняются, затем счётчик кадров стабилен; 0 новых кадров за 700 ms покоя | [Замер](assets/camera-2026-09-20/transitions.json)        |
| Unmount во время перехода | Через 750 ms roots = 0, canvas = 0; после mount по одному, 0 новых кадров за 700 ms           | [Жизненный цикл](assets/camera-2026-09-20/lifecycle.json) |
| Reduced motion            | Переход сразу получает конечные матрицы; по 2 служебных кадра на смену режима, затем 0        | [Замер](assets/camera-2026-09-20/reduced-motion.json)     |

Reduced motion переключался через тестовый MediaQueryList в диагностической
странице; системная настройка ОС не менялась. Во время редактирования самого
probe возникали предупреждения повторного createRoot при HMR; добавлен cleanup
диагностической страницы. Основной просмотрщик и production их не воспроизводят.

Физическое двухпальцевое управление и мобильный GPU не проверялись; это не замер

выполненные здесь проверки всех инструментов измерения или всех обработчиков DOM.
