# Визуальный редизайн viewer'а the_hatka_project

> Документ разбит на фазы. **Давай агенту по одной фазе за раз**, каждая заканчивается проверяемым результатом.
> Фазы 0 и 1 — фундамент, без них остальное развалится.

## Общий контекст (вставлять в начало каждой фазы)

Проект: React 19 + TypeScript + Vite, three.js / R3F. Интерактивный viewer 3D-модели квартиры.

Задача: превратить интерфейс из технического прототипа в законченный продукт для просмотра
и проектирования квартиры. Работа идёт только в presentation layer.

**Жёсткие запреты (не нарушать ни в одной фазе):**

- не менять геометрию квартиры, размеры, координаты, состав мебели;
- не менять TypeScript-описание модели и формат экспортов (model.json / glb / obj / mtl);
- не менять бизнес-логику: сохранение состояния, undo/redo, перемещение мебели, экспорт;
- не добавлять UI-библиотеки (MUI, Chakra, Ant, shadcn) — только собственные примитивы;
- не добавлять зависимости без явного обоснования в одну строку;
- не делать массовых переименований файлов и «попутного рефакторинга».

**Формат работы:** после каждой фазы — сборка, запуск, скриншот, короткий отчёт что изменено.
Если по ходу видишь проблему за пределами текущей фазы — записывай в `NOTES.md`, но не чини.

## Фаза 0. Аудит (без изменений кода)

Ничего не меняй. Прочитай код и выдай отчёт:

1. **Дерево компонентов** — что рендерит canvas, что рендерит UI, где они связаны.
2. **Layout** — как сейчас распределяется пространство, где заданы размеры canvas.
3. **Состояние** — где живёт viewer state (режим вида, флаги мебель/названия, уровень среза,
   режим перемещения, история undo/redo), как оно прокидывается в сцену.
4. **Стили** — есть ли CSS-переменные, какие значения цветов/отступов/радиусов используются,
   сколько раз повторяются одни и те же значения, где inline-стили.
5. **Сцена** — renderer settings (tone mapping, colorSpace, antialias, shadow map), источники
   света и их параметры, материалы стен / пола / мебели, настройки камеры и controls,
   как работает «Вписать модель».
6. **Labels** — как формируются подписи комнат, чем рендерятся (DOM overlay / sprite / Html),
   есть ли зависимость от дистанции камеры.
7. **Связанность** — какие UI-компоненты напрямую дёргают three.js объекты в обход state,
   и что из этого можно развязать малой кровью.

Затем — список визуальных проблем, отсортированный по влиянию на восприятие, и план фаз
с оценкой риска. **Не начинай менять код, дождись подтверждения плана.**

## Фаза 1. Design tokens + UI primitives

### 1.1 Tokens

Один файл с CSS-переменными, единственный источник правды. Стартовые значения ниже —
можешь скорректировать оттенки, но не структуру и не количество токенов.

```
/* Поверхности */
--scene-bg-center:  #1A1D21;   /* сцена: радиальный градиент, лёгкая виньетка */
--scene-bg-edge:    #0E1013;
--surface-1:        rgba(24, 27, 31, 0.92);   /* плавающие панели, поверх сцены */
--surface-2:        #22262B;                  /* hover / вложенные поверхности */
--surface-raised:   #2A2F35;                  /* active сегмент, нажатое состояние */

/* Границы и разделители */
--border:           rgba(255, 255, 255, 0.08);
--border-strong:    rgba(255, 255, 255, 0.14);

/* Текст */
--text-1:           #E8EAED;   /* основной */
--text-2:           #9BA1A8;   /* вторичный, подписи, единицы измерения */
--text-3:           #6B7178;   /* disabled */

/* Акцент — ровно один, холодный, чтобы не спорить с тёплой палитрой модели */
--accent:           #7FA6C9;
--accent-quiet:     rgba(127, 166, 201, 0.14);   /* фон активного состояния */

/* Радиусы */
--r-sm: 5px;   /* контролы */
--r-md: 8px;   /* панели */

/* Spacing — шаг 4 */
--s-1: 4px; --s-2: 8px; --s-3: 12px; --s-4: 16px; --s-5: 24px; --s-6: 32px;

/* Тени — очень сдержанные, панели «лежат» на сцене, а не парят */
--shadow-panel: 0 1px 2px rgba(0,0,0,.3), 0 8px 24px rgba(0,0,0,.24);

/* Переходы */
--t-fast: 120ms cubic-bezier(.2,0,.2,1);
```

**Типографика.** Не использовать системный стек по умолчанию. Взять один гротеск —
`Geist` или `IBM Plex Sans` (self-hosted, не CDN Google Fonts). Шкала: 11 / 12 / 13 / 15 px,
веса 400 и 500, не больше. Заголовок продукта — 13px/500, не крупнее: это инструмент, а не лендинг.
Все числовые значения (высота потолка, уровень среза, масштаб) — `font-variant-numeric: tabular-nums`,
чтобы не прыгали при изменении.

**Запрещённые приёмы:** ALL-CAPS лейблы с разрядкой, неоновые/кислотные акценты,
градиентные заливки как декор, glassmorphism с сильным блюром, эмодзи в интерфейсе,
стрелка `→` в конце текста кнопок, одинаковый radius на всём подряд.

### 1.2 Primitives

Каждый примитив — отдельный файл, стили только через токены, никаких хардкод-значений внутри:

- `Button` — variants: `primary` / `secondary` / `ghost`, sizes: `sm` / `md`
- `IconButton` — квадратный, 28 и 32px
- `SegmentedControl` — для переключения режима вида
- `Toggle` — вместо чекбоксов
- `Select` — свой dropdown, **не нативный `<select>`**
- `Tooltip` — задержка появления 400ms, без анимации ухода
- `FloatingPanel` — контейнер: `--surface-1`, `--border`, `--r-md`, `--shadow-panel`
- `StatusBadge` — для служебных значений

Общие требования ко всем: `:focus-visible` с видимым кольцом акцентного цвета,
корректный `disabled`, hover только через `--t-fast`, работа с клавиатуры
(`SegmentedControl` — стрелки, `Select` — стрелки + Enter + Esc), `prefers-reduced-motion`.

**Результат фазы:** примитивы существуют и покрыты демо-страницей или Storybook-подобным
экраном; основной интерфейс пока не тронут.

## Фаза 2. Композиция экрана

Текущее состояние: canvas уже почти во весь экран, **но модель занимает около четверти кадра** —
это проблема камеры и fit-логики, а не layout'а. Чинить нужно и то, и другое.

### 2.1 Камера и кадрирование

- «Вписать модель» должно рассчитывать bounding box модели и подгонять камеру так, чтобы
  модель занимала **не менее 80% меньшей стороны viewport**, padding 8–10%;
- этот же fit применяется при первой загрузке и при смене режима вида;
- fit пересчитывается при resize окна (debounce 150ms);
- убрать рамку/border вокруг canvas — сцена идёт под край окна.

### 2.2 Layout

Canvas — full-viewport, `position: fixed`, слой 0. Весь UI — плавающие слои поверх него.

```
┌──────────────────────────────────────────────────────────┐
│  ⌂ Хатка   Квартира 66 м²                 [Скачать GLB]  │  ← header, height 48
├──────────────────────────────────────────────────────────┤
│ ┌──────────┐                                             │
│ │ 2D       │                                             │
│ │ 3D       │  ← вид, вертикальный segmented, слева        │
│ │ Разрез   │                                             │
│ └──────────┘                                             │
│ ┌──────────┐                                             │
│ │ Мебель  ◉│                                             │
│ │ Названия◉│  ← один controls group, под переключателем   │
│ │ Срез 1,05│                                             │
│ └──────────┘                                             │
│                                                          │
│                      [ модель ]                          │
│                                                          │
│                                    ┌──┐                  │
│                                    │⤢ │  ← fit           │
│                                    │⌂ │  ← сброс камеры  │
│                                    │▣ │  ← вид сверху    │
│                                    │+ │                  │
│                                    │− │                  │
│                                    └──┘                  │
│ ┌────┬────┐                          Потолки 2,70 м      │
│ │ ↶  │ ↷  │  ← undo/redo             Срез 1,05 м    (?)  │
│ └────┴────┘                                              │
└──────────────────────────────────────────────────────────┘
```

Принципы композиции:

- **Header** — минимальный: название, подзаголовок, справа «Скачать GLB» как `secondary` кнопка
  (сейчас это подчёркнутая ссылка — самый заметный элемент на экране, что неверно);
- **Режим вида** — `SegmentedControl` слева сверху, вместо нативного select;
- **Мебель / Названия / уровень среза** — один `FloatingPanel` под переключателем режима;
  уровень среза показывается и меняется только когда активен режим разреза;
- **Camera controls** — один вертикальный `FloatingPanel` справа снизу: вписать, сбросить,
  вид сверху, зум +/−;
- **Undo/redo** — слева снизу, отдельной парой, визуально тише камеры;
- **«Перемещать»** — это режим, а не действие: сделать `Toggle` или кнопку с явным
  активным состоянием, в группе с остальными переключателями;
- **Служебные значения** (потолки, уровень среза) — `StatusBadge` справа снизу, `--text-2`,
  11px, без рамки;
- **Инструкция по управлению** — убрать с экрана, спрятать под иконку `(?)` рядом со статусом.

Порядок внимания при первом открытии: **квартира → режим вида → инструменты → настройки.**
Ничто в UI не должно быть контрастнее самой модели.

**Результат фазы:** новая композиция работает, все существующие функции на месте.

## Фаза 3. Подписи комнат и camera UX

### 3.1 Labels

Сейчас — тяжёлые тёмные плашки с высоким контрастом, все одного размера, доминируют над сценой.

Переделать:

- 11px, `--text-1`, фон `rgba(16,18,21,0.72)` + `backdrop-filter: blur(6px)`, radius 4px,
  паддинг 3/7, без рамки;
- центрирование по центру помещения, не по стене;
- **приоритеты**: комнаты > 8 м² видны всегда; мелкие (санузел, гардеробная, балкон)
  скрываются при отдалении камеры дальше порога;
- при сильном отдалении гасить плавно через opacity, не резким unmount;
- на верхнем виде (2D) подписи можно показывать все — там места достаточно;
- проверить перекрытие подписей друг другом при малых углах камеры.

### 3.2 Camera UX

- при первом заходе (`localStorage` флаг) — короткая подсказка на 4 секунды: вращение,
  перемещение, масштаб. Одним компактным блоком, затем исчезает и больше не возвращается;
- та же подсказка доступна по кнопке `(?)`;
- `damping` у controls включён, `dampingFactor` умеренный — движение должно ощущаться плотным,
  а не инерционным;
- **сброс камеры** возвращает в исходный ракурс, **вписать модель** — кадрирует текущий ракурс,
  **вид сверху** — ортогональный сверху. Это три разных действия, не дублировать;
- переходы камеры между пресетами — анимированные, 400–500ms, easing `easeInOutCubic`;
- ограничить `maxPolarAngle`, чтобы нельзя было уйти под пол.

## Фаза 4. Качество 3D-сцены

Цель — clean architectural visualization, не photorealistic renderer. Каждое изменение
проверять по FPS: если эффект стоит больше 15% производительности — отказаться.

- **Renderer**: `outputColorSpace = SRGBColorSpace`, `toneMapping = ACESFilmicToneMapping`,
  `toneMappingExposure` подобрать в диапазоне 0.9–1.15, `antialias: true`,
  `pixelRatio` ограничить `Math.min(devicePixelRatio, 2)`;
- **Фон сцены**: радиальный градиент `--scene-bg-center → --scene-bg-edge`, реализовать
  дёшево (CSS под canvas или шейдерная плоскость), не HDRI-скайбокс;
- **Environment**: мягкое студийное окружение низкого разрешения для бликов на мебели,
  `environmentIntensity` небольшой. Без HDR-файлов на несколько мегабайт;
- **Directional light**: один ключевой, тени PCFSoft, shadow map 2048, bias подобрать
  чтобы не было acne и peter-panning; угол — чтобы стены получали разную освещённость
  и не сливались друг с другом;
- **Ambient / hemisphere**: мягкий подсвет теней, холодный сверху — тёплый снизу,
  очень слабый, чтобы тени не были чёрными;
- **Contact shadows** под мебелью — главный источник ощущения «предметы стоят на полу»,
  дешевле полноценных теней, ставить обязательно;
- **AO**: только если после остального объёма всё ещё не хватает. Тогда — дешёвый вариант
  (N8AO или SSAO с малым радиусом), не дефолтный тяжёлый пост-процесс;
- **Материалы**: стены — `roughness` 0.85–0.95, `metalness` 0, цвет не чисто белый,
  а очень светлый тёплый (#F2EEE8-ish); разные стены не должны сливаться — разница создаётся
  светом, а не разными цветами; пол — заметно теплее и темнее стен; мебель — умеренный
  контраст с полом;
- **Edges**: проверить, нужен ли лёгкий outline на срезах стен — тонкая тёмная линия
  по кромке среза сильно улучшает читаемость плана. Если да — дешёвый вариант
  (материал кромки), не `EdgesGeometry` на всей сцене.

Ключевой критерий: светлые стены читаются раздельно, но не выглядят серыми или грязными.

## Фаза 5. Responsive и polish

Проверить и зафиксировать скриншотами: **1920×1080, 2560×1440, 1440×900**.

- на 1440×900 панели не должны съедать больше 20% ширины;
- на 2560×1440 UI не должен «тонуть» — плавающие панели не растягиваются,
  но и не выглядят потерянными: отступы от краёв экрана растут вместе с viewport;
- `pixelRatio` и размер shadow map — не привязывать к разрешению экрана линейно;
- `:focus-visible` виден на всех интерактивных элементах;
- `prefers-reduced-motion` отключает анимации камеры и переходов;
- ни одного нативного `<select>`, `<input type=checkbox>` или `<button>` без стилей
  в финальном билде.

## Definition of Done

Фаза считается принятой, когда:

1. `npm run build` проходит без ошибок и новых warning'ов;
2. приложение запущено, сделаны скриншоты до/после;
3. **regression-чеклист пройден вручную:**
   - [ ] переключение режимов вида работает во все стороны
   - [ ] «Мебель» скрывает/показывает мебель
   - [ ] «Названия» скрывает/показывает подписи
   - [ ] режим перемещения мебели работает, объекты двигаются
   - [ ] undo/redo откатывает и возвращает перемещения
   - [ ] зум +/− и колёсико работают
   - [ ] «Вписать модель» кадрирует корректно в каждом режиме вида
   - [ ] «Скачать GLB» отдаёт валидный файл
   - [ ] уровень среза меняется и отображается корректно
   - [ ] после resize окна сцена не ломается
4. FPS в 3D-режиме не ниже, чем до изменений;
5. `git diff --stat` не содержит файлов модели и экспорта.

Итог всей работы: страница выглядит не как dev-tool с Three.js canvas, а как самостоятельный
инструмент для просмотра и проектирования квартиры — чисто, спокойно, без декоративного перегруза.
