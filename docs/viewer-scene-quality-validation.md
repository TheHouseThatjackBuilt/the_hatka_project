# R4.1 — свет и профили графики

Приёмка 2026-09-23. Область: фон, базовый свет, представление материалов,
настройки renderer и выбор производительности. По уточнению пользователя VR
отложен целиком: Meta Quest 3, автономное использование и подключение к ПК —
контекст будущей отдельной задачи, без VR-профиля и WebXR в текущем коде.

## Реализация

| Профиль            | Максимальный DPR | Тени           |
| ------------------ | ---------------- | -------------- |
| Быстрее            | 1                | Нет            |
| Баланс (начальный) | 1,5              | PCFSoft, 1024² |
| Качество           | 2                | PCFSoft, 2048² |

Фактический DPR ограничен также DPR устройства. Выбор действует до перезагрузки,
не сбрасывает камеру, измерения и видимость. Модель одинакова во всех профилях.
Свет пересоздаётся при смене профиля: R3F освобождает старую карту теней;
JSX-материалы и общие геометрии не пересоздаются. В «Быстрее» глобальная поддержка
теней renderer включена, но теневого источника и прохода shadow map нет.

После configure R3F явно закреплены sRGB, ACESFilmic, exposure 1; antialias включён.
Существующий радиальный CSS-фон под прозрачным canvas сохранён. Один directional
интенсивностью 2,8 и hemisphere 1,25 с холодным верхом и тёплым низом заменяют
прежние два directional и hemisphere 1,7. Для штукатурки только в viewer:
цвет #f2eee8, roughness 0,92, metalness 0. Пол и мебель сохраняют палитру модели;
уменьшение заполнения делает грани и тени заметнее. Bias −0,00025 и normalBias
0,025 сохранены после визуальной проверки. Экспорты не менялись.

## Метод замеров

Dev-сборка, Windows, Chromium 153, NVIDIA RTX 5080 через ANGLE/D3D11,
1280×720, DPR устройства 1. Cut, мебель и названия включены, измерения закрыты.
Диагностический [probe](assets/scene-2026-09-21/probe.tsx) запускает три прогона:
reset, 650 ms ожидания, вращение кнопкой каждый RAF, 1 s прогрева и 3 s выборки.
После остановки — 650 ms стабилизации и 700 ms замера покоя.
CPU submission — время между addEffect и addAfterEffect, включая подготовку
кадра и отправку WebGL-команд, не GPU timer. Число calls в gl.info относится
к основному проходу и не отражает всю стоимость теневого прохода.

Исходная версия для сравнения: `c2007ef8c022adf750f9b6f1061d0dcd69d4f426`,
распакована через git archive в игнорируемую `.tmp/r41-baseline`, сервер 5176;
новая версия — сервер 5175. Использован одинаковый probe. На исходной версии
селектор графики отсутствует, остальная композиция и сценарий совпадают.

| Сцена    | FPS, диапазон трёх прогонов | CPU submission median, ms | p95 интервала кадра, ms |
| -------- | --------------------------- | ------------------------- | ----------------------- |
| Исходная | 206–238                     | 3,2–3,9                   | 5,0–6,1                 |
| Быстрее  | 240–240,3                   | 2,1–2,2                   | 4,9–5,0                 |
| Баланс   | 216–235                     | 3,4–3,8                   | 5,0–5,6                 |
| Качество | 237–238                     | 3,0–3,2                   | 4,9–5,0                 |

Во всех 12 прогонах idleDelta = 0. Диапазоны теневых профилей перекрываются
с исходной версией; точный процент ускорения из этих шумных замеров не следует.
«Быстрее» снижает время CPU submission и не выделяет текстуру теней.
На DPR 1 различие «Баланс»/«Качество» ограничено картой теней; здесь нет
монотонного роста FPS при уменьшении разрешения карты, возможны прогрев и шум.
Сырые данные: `before-performance.json`, `performance-performance.json`,
`balanced-performance.json`, `quality-performance.json` в папке артефактов.

Проверка повторного mount в StrictMode: после unmount roots/canvas = 0/0,
после mount = 1/1, счётчик кадров в покое 1 → 1. При переключении проверены
реальные карты 1024²/2048² и отсутствие карты в «Быстрее», память геометрий
остаётся 3, текстур — 1 с тенями и 0 без них. Положение камеры после вращения
сохраняется при смене профиля. Ошибок и предупреждений браузерной консоли нет.

Числа относятся к этой машине и dev-сборке; мобильный GPU и экран с высоким
DPR не измерены. Ограничения DPR проверены отдельно Node-тестом. Эти замеры
не задают гарантию FPS на других устройствах и не подтверждают будущую VR-нагрузку.
